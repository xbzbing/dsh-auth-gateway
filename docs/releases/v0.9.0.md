## 主要变更

- **dsh 0.2.3 起改用官方 `connection.authentication` 认证提供者**：进程内随机凭据请求头在回环跳传递，登录链路不再依赖上游 BrowserAuth cookie；0.2.2 及以下保留 cookie 签发回退路径（#36，依据见 [ADR-0001](https://github.com/xbzbing/dsh-auth-gateway/blob/main/docs/zh/adr/0001-official-authentication-provider.md)）
- **bundle patch 禁用 dsh 0.2.3 的 `remote-connection`**：避免远程连接面绕过网关的回环绑定（#36）
- **账号登录回调保留浏览器回环 Host**：适配 dsh 0.2.3 按 Host 匹配回调，`/oauth/callback` 不再 404（#36）
- **支持区间上移至 dsh 0.2.3**：README、ADR 与双语部署/排障文档同步收窄版本线口径（dsh 0.1.2–0.2.2 铸 cookie，0.1.5-rc.2 起走 provider 注入）
- **修复**：认证提供者注册超时（10s）改为抛错终止启动，消除「启动成功但全部转发 401、登录页却正常」的降级态（#36）
- **修复**：`isLoopbackAuthority` 拒绝 `:0` / `:99999` 等非法端口，与 dsh `loginOrigin` 的 `new URL()` 口径一致（#36）
- **修复**：`publicPaths` 路由注册抽出 `#registerPublicPaths()`，构造函数不再越过千行检查线（#36）
- **内部**：GitHub Actions 全套门禁（check × Node 20/22/24、client 产物新鲜度、lock 源检查）与发版 workflow——OIDC 发 npm（`--provenance`）、双语 Release 正文、tgz 附件、`assert-pack` 打包断言；PR #36 的 8 条评审意见全部处理并逐条回复

## English

- **Official `connection.authentication` provider from dsh 0.2.3 on**: an in-process random credential header now crosses the loopback hop, so login no longer depends on the upstream BrowserAuth cookie; dsh 0.2.2 and below keep the cookie-minting fallback (#36, rationale in [ADR-0001](https://github.com/xbzbing/dsh-auth-gateway/blob/main/docs/en/adr/0001-official-authentication-provider.md))
- **The bundle patch disables dsh 0.2.3's `remote-connection`**: keeps the remote-connection surface from bypassing the gateway's loopback binding (#36)
- **The account-login callback keeps the browser's loopback Host**: matches dsh 0.2.3's Host-based callback matching so `/oauth/callback` no longer 404s (#36)
- **Support window moved up to dsh 0.2.3**: README, the ADR, and the bilingual deployment/troubleshooting docs now scope the version lines consistently (cookie minting for dsh 0.1.2–0.2.2, provider injection from 0.1.5-rc.2)
- **Fix**: provider registration timeout (10s) now aborts startup instead of degrading into "started, login page fine, every forward 401" (#36)
- **Fix**: `isLoopbackAuthority` rejects invalid ports like `:0` and `:99999`, matching dsh `loginOrigin`'s `new URL()` semantics (#36)
- **Fix**: `publicPaths` route registration extracted into `#registerPublicPaths()`, keeping the constructor under the thousand-line check line (#36)
- **Internal**: full GitHub Actions gates (check × Node 20/22/24, client artifact freshness, lockfile registry check) and the release workflow — OIDC npm publishing (`--provenance`), bilingual Release bodies, tgz assets, and the `assert-pack` assertion; all 8 review comments on PR #36 addressed and answered in thread
